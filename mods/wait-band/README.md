# wait-band

让 Claude Code 的 agent 等东西时**不白等**：命令跑着、静着、卡死、报错、退出一眼分得清，后台的卡住了会主动叫 agent。

两件东西，一个目录：

| 部件 | 是什么 |
|---|---|
| `bin/waitfor` | Perl 脚本。包住一条命令：必有上限、报错行当场标出、静太久标「卡住」、对方断了当场退；每秒写状态到 `/tmp/waitfor/p<Claude 进程号>/<pid>.json`，完整输出写同名 `.log` |
| `hooks/register.tsx` | Claude Code 插件：读状态、开收 `/w` 窗、后台卡住叫 agent |
| `hooks/spin.tsx` | 格子里那颗星标（surface 模块）：在界面那边转 Claude Code 自己那套 `· ✢ ✳ ✶ ✻ ✽`（250ms 一帧），占固定 1 格、不推标题；格里的字是 Button，点它开 `/w`（Button 才算人按的，窄屏也开得出来） |

## 装

```sh
git clone https://github.com/ooooxo/ooooxoskill.git
sh ooooxoskill/mods/wait-band/install.sh   # 链 ~/.claude/tools/waitfor，加进 settings.json 的 CLAUDE_CODE_PLUGIN_DIRS；重复跑无副作用
```

重启 Claude Code 生效。只用 macOS 自带的 perl、osascript。以前从压缩包装过的，照上面装一遍就行：`install.sh` 会把别处的旧 wait-band 从 `CLAUDE_CODE_PLUGIN_DIRS` 摘掉，不会加载两份。

更新：`git -C ooooxoskill pull`，重启 Claude Code。

## waitfor 用法

```sh
waitfor [-l id] [-t 标题] [-p] [-q 秒] [-Q] [-x] [-E 正则] <秒|auto|0> -- <命令…>                          # 跑到结束
waitfor [-l id] [-t 标题] [-p] [-q 秒] [-Q] [-x] [-E 正则] <秒|auto|0> <成功正则> [<失败正则>] -- <流命令…>   # 等某一行
```

| 选项 | 意思 |
|---|---|
| `-l id` | 稳定的内部名，英文短横线（`morii-cargo-check`），同一件事每次同一个：往常耗时按它记（最近 5 次成功的中位数，`~/.claude/tools/.waitfor-history`，最多记 300 个），插件按它认后台任务 |
| `-t 标题` | 给人看的短标题，几个字说干什么（「检查 Morii」）：终端进度和状态条显示它，不给就显示 id。改标题不影响往常耗时 |
| `<秒>` | 上限；`auto` = 往常×3（至少 60），头一回 1800；`0` = 不设（长轮询这类本来就等不定时长的） |
| `-q 秒` | 静多久算卡住，默认 60，`0` 不判。按这条命令正常会静多久填，宁大勿小 |
| `-p` | 挂着等人：长轮询这类等的是人、挂几小时没输出都正常的（dc 的 `/__lab/wait`）。不判卡住、不叫 agent、不记往常耗时、不刷进度行，状态条上一格绿色「◌ 标题 12m」（等你处理）、排最后、不触发自动开窗。`<秒>` 写 `0`；结束照常由后台完成通知叫 |
| `-Q` | 卡住就停掉（退出码 4）。前台跑、想早点拿回控制权时用 |

**卡住**有两种：静默卡住（静了 `-q` 秒），和**报错循环**——同一条报错（数字抹掉后比，时间戳、端口、第几次不同也算同一条）出现 ≥3 次、首尾隔 ≥10 秒。后者是重试死循环、崩了又起：一直有输出所以不「静」，但同样没进展。编译一下吐一串同样的错不算（间隔太近，马上会退），测试挂了好几个不同用例也不算。

| `-x` | 撞上第一条报错行就停掉（退出码 1）。默认只标出来、不杀 |
| `-E 正则` | 报错行认法；`-E ''` 关掉（翻日志的命令——`log show`、`journalctl`——输出里本来全是别人的报错，要关）。默认只认行首长得像报错的形状，正反例在 `tests/err-cases.txt`，改了跑 `sh tests/err-regex.sh` |

退出码：`0` 成功 · `1` 失败 / 撞失败正则 / `-x` 报错行 · `2` 超时 · `3` 流先断了 · `4` `-Q` 卡住或报错循环 · `5` 被手动停止（`/w` 里点行首的 ✕，或 kill 它；连子进程一起停）。非 0 都附最后 20 行和日志路径。停进程先 TERM，5 秒不退再 KILL。

## 插件做什么

- **输入框上方**：格子，一行最多 3 格、格宽按可用宽度均分（和条数无关，条目来去位置不跳；窄到一格不足 24 列就少放几格，多的折行）。每格 `符号 标题 … 已等/往常`（右对齐，一律按秒；命令自己报了进度——`[n/m]` 或 `n%`——就只显示百分比、不显示时长，`/w` 窗里同样），出事的换成红色原因。橙色星标转 = 在跑（窗口不在前台、或要求少动效时停住），琥珀星标 = 静了、快算卡住（`-q 0` 的不判，一直橙色），红星标 = 出过报错还在跑，红色 ! = 卡住或报错循环，绿色 ◌ = 等你（`-p` 挂着等人），✗ = 退出 / 失败，✓ = 完成（结束的留 8 秒）。不放顶部：那层只在全屏布局、只画在空白格，实际常看不见。行右的 `[-]` 是 Claude Code 自带的折叠钮（ctrl+x ctrl+a），插件去不掉。
- **点那一行**（或 ctrl+x tab 聚焦后 Enter）、或敲 **`/w`**：开窗看全部（窗开着时输入框上方那一行收起，不重复显示），每条一行带 24 秒输出波形，指针移上某行，行首露出红 ✕，点它停掉那条（连子进程一起停，退出码 5，agent 收到的完成通知写明是人停的），点行的其余地方 / Enter 展开最后 5 行和日志路径，Esc 收起。
- **叫 agent**：只对后台任务（`run_in_background` 发出的、按 `-l` 认），只在卡住（含报错循环）时叫：`[waitfor] 「标题」(id) 静 Ns，疑似卡住 · 最后一行：… · 日志路径`，或 `… 同一条报错反复 N 次，疑似重试死循环 · 报错：… · 日志路径`，每条每种只叫一次。出过报错行后卡死也算卡住。零星报错只在状态条标红、不叫——命令很快会退，后台完成通知自带最后输出；边跑边叫只会让 agent 半途动手。
- **不改命令**：插件只记下哪些 Bash 是后台跑的（按标签对上 waitfor 的状态），不改写输入——改写会让 auto 模式的审查对不上、每条都被拦。没套 waitfor 的后台命令插件看不见。
- **收尾**：结束 2 分钟的状态文件删掉；一天没动的会话目录清掉。
