**凡是要等的都尽可能走 `~/.claude/tools/waitfor`，带 `-l id -t 标题`**：`-l` 是稳定的英文 id（`morii-cargo-check`，同一件事每次同一个，往常耗时按它记），`-t` 是给人看的几个字（「检查 Morii」）。
- 预计超过 15 秒的命令：`waitfor -l id -t 标题 auto -- <命令>`；等日志里某一行：`waitfor -l id -t 标题 <秒> <成功正则> [<失败正则>] -- <流命令>`。
- 挂着等人的长轮询（dc 的 `/__lab/wait` 这类，等的是用户、多久都正常）：`waitfor -p -l id -t 标题 0 -- curl …`，不加 `--max-time` / `-q`。
- 报错行默认只标不杀，`-x` 撞上就退；`-q 秒` 是静多久算卡住（按这条命令正常会静多久自己填，宁大勿小），前台想卡住就退加 `-Q`。
- 后台的卡住了（静默卡住，或同一条报错反复出现 = 重试死循环）插件会发 `[waitfor]` 消息叫你，带最后一行 / 循环的报错和日志路径：先判断是卡死还是慢、循环的原因修不修得了，再决定等、kill 还是换做法。前台加 `-Q` 两种卡住都直接停。
