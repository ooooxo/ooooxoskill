# Morii Compare —— 对照版

**用户说「给我几套看看」，交付物永远是一页能切档的对照 HTML，不是一段文字描述。**
看得见才判得准；文字描述的方案，用户只能凭想象判，判完还得重来一轮。

一句话流程：**先问清比什么 → 定样本与第 0 档 → 写 ≥5 档完整方案 → 拍图自检 → 起服务、开一次页面 → 挂在 `/__lab/wait` 上等 → 用户标注发来就改、回话、再等。**

页面长相（模板已做好，别改骨架）：**顶条在上，左栏看哪个，右栏滑块，右下角发送，其余全给生成的内容**——
- **顶条**（只放「怎么看」，不放说明字）：题目 · 交互 / 拼装 · 标注 · 钉住 ｜ 样本 · 单看 / 对照 / 全档 / 全部界面 · 比例 % · 明暗 · 记录 · 滑块 · 键位。
- **左栏**一座岛：**界面清单**（比几个界面才有，行尾是它当前选的档）→ **轮次**（多轮才有，一颗按钮点开全部，`R` / `⇧R`）→ **档清单**（选中那档就地展开论点 · 零件 · 代价）。
- **右栏**：**你按题目定的滑块**（轮次共用 + 选中档私有），用户只管拉、不让加减；不常用，`I` 收起。
- **右下角**：**反差色悬浮「发送」**（`⌘⏎`；有没发的标注带个数），上面一小摞是 agent 的回话与标注清单。**没有 agent 状态字**。
- 舞台**默认一次只看一档**（数字键 / ← → 换档，**直接换、不淡出不入场**，只有首屏与 `P` 重播才逐格入场）；
  `C` 现状对选中，`A` 本界面全部档，`G` **全部界面并排**——每格头上一排档号，**各界面各切各的档**，切到哪档就是选了哪档。
- 「记录」= 交互动作、改动、标注、发送、agent 回话的一条时间线，**撤回不占界面**：⌘Z / ⇧⌘Z，撤回过的变灰。

## ① 开工前：三件事问清（能从代码查到的就去查，不问）

1. **比的是什么维度。** 「整块重做」和「只换按钮皮」是两种对照。先定哪些**可以变**、哪些**已经定了不许动**
   （已定的每一档都遵守 —— 否则档与档之间同时在变好几样东西，用户没法判是哪一样好）。
2. **痛点原话。** 用户圈出来的那几处就是验收标准。每一档都要回答那几处，答不上的档不出。
3. **样本从哪来。** 见 ②。

问法：一次一个问题，附上推荐答案（grilling 的问法）。已经能从代码 / CONTEXT / ADR 读到的，不问。

## ② 样本：真形状，≥3 条，覆盖稀 / 中 / 满

- **样本的字段、动作、状态照项目里真的 schema / 组件抄**；数可以造，形状必须是真的。
  用户截图里那一条必须在样本里。
- 至少三条，刻意挑出**极端**：稀（一两格、没有主角）· 中（用户截图那条）· 满（动作多、字段多、全部零件都有）。
  一个方案在稀和满两头都站得住才算站得住。
- 一条样本不够暴露某个毛病时（例如「挤了会怎样」），**补一条能暴露它的真样本**，别调参数假装。
- **第 0 档永远是现状**，照现行代码抄（类名、间距、墨阶照搬），不画成稻草人。单看时按 `0` 就是它；`C` 把现状与选中档并排细看。
- 样本一次只看一条（顶条段控 / `S` 切），换档、全档平铺都对着同一条样本——判的是档，不是样本。
- **样本 ≠ 界面**：稀 / 中 / 满是同一个界面的不同数据；工单页、事件页是不同的**界面**，各写一个 `PAGES` 项（见 4.2），别把界面塞进样本。

## ③ 档：≥5 套完整方案，每套一个论点

- **至少 5 档（不含现状），建议 6–8。** 少于 5 档没有选择余地；超过 10 档用户看不完。
- **每档是一套完整方案，不是一个零件。** 每档都把所有样本、所有部位画全。
- **比几个界面，每个界面各有自己的一套档**（档的设计各界面各不相同，第 0 档各是各的现状）；每个界面都守这一节的数量与论点要求。
- **每档一句论点**（它相信什么：「动作沉底」「状态是一条路」「值本身就是控件」），外加一排零件标签
  （`动作 底栏` `字段 窄标签列` …，一个参数一枚 chip，不用 `·` 串）和**一行代价**（它牺牲了什么，琥珀色）。
  写不出代价的档，要么是没想透，要么是稻草人。
- 档与档之间**只变同一组维度**；覆盖度优先：每个可变部位的每种做法至少在一档里出现一次，用户才能说「3 的路轨 + 1 的底栏」。
- **用户否过的方向**（项目记忆 / 口味清单里）可以放一档当对照，但代价行里写明「否过」。
- 守项目的设计系统：只引 token、不写裸色值；morii-design 的铁清单照走（一屏一颗主键、不许一个控件独占一行、选中不铺色块……）。

## ③½ 静态稿还是可交互稿

**默认是可交互稿**：模板默认只开「交互」，样本里的按钮、⋯ 菜单、编辑真能用（每一下记进「记录」）。
**「拼装」默认关**，用户要挪零件时自己开（顶条或 `M`）：开了之后**颗粒度到每一个小组件**——指针下是哪个就拖哪个
（按钮、图标、标题字、标签、一段说明各自能挪；控件整颗不拆，按钮里的图标随按钮走），悬停有框与名牌，
框右下角拉手改大小（吸 8px，Shift 不吸），双击连位置带大小归位，**⌥ 拖抓整组**（最近的具名零件）。比的是**行为**（状态、流转、点了之后怎样）时，必须写成真能点的：
按钮带 `data-act`、该开的菜单能开（`data-menu` + 轮次 `menu`）、该变的状态真变（轮次 `on`），别画一张图假装。

两颗都关 = **静态**：样本不响应指针，顶条长出「钉住」（常态 / 悬停 / 菜单开…），把某个状态摆出来（`A` 平铺时所有档同时摆）。
只比**外观**、或要截图对比某个瞬间时用它。钉住的状态在 `round.pins` + `round.pin(root, id, spec)` 里写。

**标注**（`F`，独立一颗，开着时盖过看法）：像在设计稿上留评论——指针下的组件有框与名牌，点哪儿就在哪儿落一枚带号的点，
贴着点长出一个小框写一句「这里要改什么」（⏎ 存、⇧⏎ 换行、Esc 放弃、点外面也存）。
**点绑在组件上，不是格内坐标**：记的是哪个组件（具名 / 路径 + 标签）和点在它里面的比例位置；组件一动（抽屉滑出、页签切换、拼装挪位）点逐帧跟着走，
组件看不见（抽屉收起、页签切走）点就藏，滑出格子的剪掉；交给 agent 的也是组件（`组件 / 路径 / 原文 / html`），不是坐标。组件被 agent 改没了才落回记下的坐标。
点可以落在任何界面、任何档、任何样本上；右下角那一摞列出全部，点一条跳过去改 / 删。发出去的点变灰，agent 回话后消失。
想说整体的话，就点在格子空白处（认成「整格」）。
**你不用为标注写任何东西**：组件认法同拼装（没命名的按路径），给要跨档比的零件命名（`pa` / `part`）能让标注里的「组件」读得更明白。

## ④ 骨架：台子是共享的，页面只写第 ② 段

**台子只有一份**：本目录 `lab.js` + `lab.css`（顶条、左栏清单、右栏滑块、记录、标注、发送、舞台引擎），对照版服务在 `/__lab/lab.js` · `/__lab/lab.css` 下发。
**对照页只是一个壳**（`template.html`）：head 里 link 项目 token 与台子，body 里一段 `<script type="module">` 写第 ② 段，末尾 `labStart({ TOPIC, KEY, CSS, PAGES })`。
- 台子一改，所有开着的对照页自己刷新换上；**别往页面里抄台子，也别为一页改 `lab.js`**（要改台子就改这一份，所有页面一起受益）。
- 第 ② 段是自己的模块作用域，名字随便起，**不会和台子撞**；几个界面写在一页也不用手工包作用域。
- 页面**必须经对照版服务打开**（`lab.sh`，见 ⑦）；直接双击文件，台子加载不了。
- 壳**不带任何示例内容**——样本、样式、档全由你按题目现写，别从别的对照页抄内容过来（抄来的档会把这一题的判断带偏）。第 ② 段没填，页面会在舞台上报错并抛异常。

### 4.1 拷过来，改头部

复制本目录 `template.html` 到项目 `docs/lab/<topic>.html`（没有 `docs/lab/` 就建）。台子那两行（`/__lab/lab.css`、`/__lab/lab.js`）原样留着：

| 改什么 | 怎么改 |
|---|---|
| token | `<link>` 指向项目的 token 源（Hrige：`../../src/styles/tokens.css` + `control.css`；Morii 仓内：`src/panel/shell/tokens.css`；没有项目 token：把 morii-design 的 `Token.css` 拷到页面旁边） |
| 图标 | 全局 `ICON` 是台子自用的几枚；样本要用的从项目图标注册表抽出来，在第 ② 段 `Object.assign(ICON, { 名: "<path …/>" })` 补进去，**不手画**；缺的走 morii-icon |
| 项目自己的零件库 | 有（如 Coffice 的 `prop-kit.js`）就在 head 里台子前面再 `<script src>` 一行，第 ② 段直接用 |
| 页头注释 | 干什么 / 怎么跑 / 需要什么三行，写这一题的 |

### 4.2 填第 ② 段（只有这一段归你）

按这个顺序写：

1. **`TOPIC` / `KEY`**：题目名；`KEY` 是 localStorage 前缀，一题一个（`lab.<topic>.`）。
2. **`CSS`**：所有界面共用的样本样式。只进影子，只吃 token 与 `var(--p-*)`；**样本的样式绝不写进页面 `<style>`**（那是台子的）。
   样本最外层自己画面（底、圆角、影）；拼装时要让零件能拖出边，就给它加 `:host([data-mode~="build"]) .你的外框 { overflow: visible }`。
3. **`PAGES`**：比几个界面就写几项（只比一个就写一项）。每项 `{ name, specs, css, rounds }`：
   - `name`：左栏界面清单上的名字。
   - `specs`：这个界面的样本，≥3 条（稀 / 中 / 满，见 ②）。台子只读 `from`（顶条样本段控上的字）与 `note`（悬停提示）；其余字段照项目真 schema。
   - `css`：这个界面所有档共用的样式（可不写）。
   - `rounds`：这个界面的轮次，写法见下（`ROUNDS` 那张表就是每一轮的字段）。各界面的轮次互不相干，各自往下开。
   只比一个界面也可以不写 `PAGES`：`labStart({ TOPIC, KEY, CSS, SPECS, ROUNDS })`，台子当成一个界面。
   台子给第 ② 段的全局只有五个：`ICON` · `ic(名, 尺寸)` · `pa(id, 名)` · `part(id, 名, html, cls?)` · `labStart(配置)`。
4. **每一轮**（`PAGES[i].rounds` 里一项）：下一轮在末尾追加、上一轮原样留着。字段：

| 字段 | 必填 | 是什么 |
|---|---|---|
| `name` | 是 | 轮名，顶条上切轮次用 |
| `tile` | 是 | `{ w, h }` 每格多大：数字（px），或一个共用参数的 key（格子跟着那条滑块变） |
| `list` | 是 | 档：`{ name, thesis, parts: [[键, 值], …], cost, css, params, render(spec) }`；第一轮第 0 档 = 现状 |
| `params` | 否 | 共用滑块，见下 |
| `menu` | 否 | `(spec, btn) => [{ label, danger }]`：样本里带 `data-menu` 的按钮弹出的菜单 |
| `on` | 否 | `(act, { root, spec, btn, log }) => void`：带 `data-act` 的元素（按钮或整行）被点时的真行为（改名、换状态…）；不写就只记一笔 |
| `pins` + `pin` | 否 | 静态看法下可钉住的状态 `[[id, 名], …]`，`pin(root, id, spec)` 把影子里的样本摆成那样（可调台子的 `openMenu(root, btn)`） |
| `figure` | 否 | `(v, d, box) => HTML`：记录弹层顶上的示意图，`v` 当前值、`d` 默认值；`.fig-ghost` 画默认虚影、`.fig-face` 画当前实面 |

### 4.3 `render` 怎么写

- 返回这一档在这条样本上的 HTML，台子包进影子里的 `.root`。
- **拼装不用你套壳**：台子自动认到每一个小组件。没命名的零件按「样本 + DOM 路径」记，只在那条样本上生效、名字取文字 / `aria-label`。
- **给要跨档比的零件命名**（主键、标题、状态章、动作栏这类用户会说「把 3 的 X 挪到 1」的）：
  单个元素直接写属性 `<button ${pa("send", "发送")}>`；一组用 `part(id, 名, html, cls?)` 套壳（⌥ 拖抓的就是它）。
  `id` 跨档同名，命了名的挪位换样本也跟着走，记录与拷出的 JSON 里也叫这个名。
  拉过大小的零件宽高直接写在它身上（套壳的组则内容撑满壳），所以零件内容要能跟着宽高走（弹性排布、别写死尺寸）。
- **外框自己画**：台子只给一个空的 `.root`，样本的面（底、圆角、影、`overflow`）由 `render` 返回的最外层画。
- 能点的写成能点的：动作按钮带 `data-act="动作名"`，菜单按钮带 `data-menu`（见 ③½）。
- 只用 token、`var(--p-*)` 与 `ic()`；档自己的样式写进它的 `css` 字段。

### 4.4 滑块由你决定（用户只管拉，不让用户自己加减）

- 只放会左右判断的那几条，一轮 **2–6 条**，不是把所有 CSS 值都摆出来。
- 写法 `{ key, label, min, max, step, tick, def, unit }` → 影子里读 `var(--p-<key>)`。
  所有档都受影响、要公平比较的放**轮次** `params`（右栏上标「共用」）；只有某一档才有的旋钮放**那一档**的 `params`（选中那档时才出现）。
- 范围覆盖「明显太小」到「明显太大」，`def` = 你推荐的值；`tick` 管画几道刻度，别让刻度糊成一片。
- 拉刻度轨只改变量不重画（开着的菜单不会被冲掉）；每一下都进记录，⌘Z 可撤回。

### 4.5 台子已经带好的（不用写；要改就改 `lab.js` 这一份）

`M` 轮换看法（只交互（默认）→ 两开 → 只拼装 → 静态）· 看几档（默认单看 · `C` 现状对选中 · `A` 全档 · `G` 全部界面，记在本机）·
`T` 明暗（**默认跟随系统**，手选亮 / 暗后记住）· `I` 收起滑块 · `P` 重播入场 · `?` 键位 ·
**`⌘Z` / `Ctrl+Z` 撤回改动、`⇧⌘Z` / `Ctrl+Y` 重做**（参数、回默认、零件挪位 / 归位都进记录，同名 500ms 内连改并成一条）·

## ⑤ 动效档（用户要动 / 液体 / 弹簧时）

- 动效照抄项目里已有的同类原件（Morii 的液体：`src/panel/shell/liquid/` 的几何与弹簧），**不自己拿分段曲线拼**。
- 形逐帧画成一条 path；内容按同一条 path 裁（`clip-path: path()`），**液体长到哪露到哪**。
- 大面的影用 box-shadow 投影板，小件用 svg `feDropShadow`；亮色白对白时形只靠影显形，别把影撤了。
- 必须逐帧验（见 VERIFY.md），中间帧也得成立。

## ⑥ 验收：拍了再交

照 **`VERIFY.md`**：每档 × 明暗各拍一张全景，病灶处放大裁切，动效接管 rAF 逐帧拍。
自己先挑毛病（折行、控件独占一行、字截断、竖线错位、内容露出液体外），修完再拍。
ego 截的是 Chromium：`filter` / `mask` / `clip-path` / `backdrop` 这类内核差异大的，交付时明说「WebKit 未验」。

## ⑦ 交付：起服务、开一次、挂着等

对照页由**对照版服务**托管（`serve.mjs`，零依赖 Node；**按全局规矩跑在 Docker 里**，`compose.yaml` 就在本目录）。
它干四件事：托管项目目录（token 的相对路径照常解析）· 盯 `docs/lab/`，文件一改开着的页面自动刷新 · 页面「发送」排队，你从 `/__lab/wait` 取 · **没人用了自己关**（没页面开着、没 agent 挂着、没批排队，闲 15 分钟退出，`LAB_IDLE_MIN` 可调；要用时 `lab.sh` 再起，端口不变）。

1. **起服务**，端口自动分（幂等：已经在跑就只报地址；同一项目每次同一个端口，被别人占了就往后找，几个项目同时开不撞）：
   ```bash
   ~/.claude/skills/morii-compare/lab.sh <项目根>     # 最后一行就是 <地址>，如 http://127.0.0.1:47520
   ```
   下面的 `<地址>` 都是它；忘了就再跑一次，便宜。**别自己挑端口、别直接 `docker compose up`**——端口一变，页面的源跟着变，存的选档、标注全丢。
   页面开着就一直在；关了页面、你也不挂着，过一会儿它自己关。改过 `serve.mjs`：`docker compose -p <lab.sh 报的项目名> restart`（文件是挂进去的，重启就换上新的，端口不变）。
2. **开一次**：`/usr/bin/open <地址>/docs/lab/<topic>.html`（裸 `open` 在 cmux 里可能被替身接走）。
   之后**不再 open**——你每改一次文件，那页自己刷新；用户已经开着就跳过这步。
3. **挂着等**（`run_in_background`，同一时间只挂一个）：
   ```bash
   curl -s <地址>/__lab/wait
   ```
   用户点右下角「发送」（或 ⌘⏎），curl 带着一批 JSON 退出，你被唤醒。服务重启时 curl 会空手退出（exit 52），重新挂上就行。
4. 回复里：一张表列出各档（`# · 名 · 一句话`；多个界面就每个界面一张），写明第 0 档是现状、怎么用（`F` 标注 · `G` 全部界面各切各的档 · `⌘⏎` 发送；要挪零件开「拼装」），哪些已验、哪些没验。
   最后一行：**标注要改的地方、每个界面切到想要的档，点右下角「发送」，我在等。**

### ⑦½ 收到一批之后

一批 JSON 长这样（字段名就是中文）：`页 · 题目 · 在看`（界面 · 轮 · 档 · 样本）· `选档`（每个界面当前选的档）·
`标注[]`（`号 · 界面 · 档 · 样本 · 组件 · 具名 · 路径 · 原文 · html · 要改`）· `参数`（改过的滑块，带默认值）· `布局`（拼装挪过的零件）。
`选档 / 参数 / 布局` 是**当前全量**，不是增量；`选档` 就是用户的挑选——切到哪档就是要哪档。

1. 逐条照 `要改` 改 ② 段（`路径` + `原文` + `html` 足够在 `render` 里定位；`具名` 有值就搜 `data-part`）。改不了 / 有疑问的那条，别硬改，回话里说。
2. 改完**先拍图自检**（⑥），页面已经自己刷新了。
3. **回话**（一两句：改了哪几号、哪号没改为什么），出现在页面右下角，发出去的那批点随之消失：
   ```bash
   curl -s --data-binary @- <地址>/__lab/say <<'EOF'
   1 号超时时长挪进右侧章；2 号报修键沉底，不压清单。3 号没动：要改的是第 0 档，现状不改。
   EOF
   ```
4. **再挂上 `/__lab/wait`**，然后结束这一轮回复（终端里也给一句同样的话）。用户在终端直接打字也照常处理，挂着的 wait 不受影响。
5. 用户说「就这样」或各界面的 `选档` 稳定了，按 ⑧ 开下一轮，或按 ⑨ 收尾。

丢了一批（wait 被杀、会话断了）：`curl -s <地址>/__lab/last` 取回最后交出去的那批。
用户手里只有文件、没法起服务时：先 `lab.sh` 把服务起来再给地址——台子不在页面里，`file://` 打不开。

## ⑧ 下一轮

- 用户挑完，**同一页开下一轮**（那个界面的 `rounds` 加一项，左栏轮次按钮 / `R` 切换），上一轮原样留着当判据记录。页面自己刷新，不用再 open。
- 新一轮把选中的部分**钉成底子**，只变还没定的维度，仍然 ≥4 档（收敛轮可以少于 5）。
- 每定下一条，当场写进项目的 CONTEXT.md（术语）或 ADR（难反悔、有取舍的决定）—— 项目用 domain-modeling 时照它的格式。

## ⑨ 收尾：开了什么就关什么

**每轮回复结束前**（不只是最后一轮）过一遍，开着的东西都是用户的负担——用户的浏览器里攒一堆 agent 开的标签，比没做还烦：
1. **ego 验收空间**：拍完图当场 `await task.finish({ keep: [] })`，一轮一关，不攒到最后；中途开的临时标签随手 `page.close()`。
2. **测试状态**：ego 的档案可能就是用户自己的浏览器，验完删掉这一题 `lab.<topic>.` 开头的 localStorage 键（VERIFY 6），别让用户打开看到你点过的明暗、选档、标注。
3. **wait 只挂一个**：重挂之前确认上一个已经退出（收到一批、或服务重启 exit 52）；别同时挂两个，否则一批会被旧的那个抢走。

**用户说定稿 / 不用了 / 先这样**：
4. 停掉挂着的 wait（`TaskStop` 那条后台任务）。
5. 关服务：`~/.claude/skills/morii-compare/lab.sh <项目根> stop`（不关它也会闲 15 分钟自己关，但用户明说完了就当场关）。
6. 回复里一句话交代：服务关了、wait 停了、浏览器里没留东西。

## 反模式（见一个删一个）

| 反模式 | 为什么错 |
|---|---|
| 用文字描述 N 套方案让用户选 | 用户只能凭想象判，判完还要再做一遍 |
| 第 0 档画成稻草人 | 对照失去意义；照现行代码抄 |
| 只有一两条样本，全是「中等」 | 稀和满两头才暴露毛病 |
| 档与档同时变好几样 | 判不出是哪一样好 |
| 每档只画一个零件 | 零件好看不等于整体成立 |
| 代价行空着 | 没有代价的方案是没想透 |
| 没拍图就交 | 折行、截断、错位只有眼睛看得出 |
| 下一轮另开新页、旧轮删掉 | 判据记录丢了，下次又问一遍 |
| 档的样式写进页面 `<style>` | 漏出影子、台子与样本互相污染，判的不是档本身 |
| 比行为却只画静态图 | 用户要点了才知道好不好；能点的就做成能点 |
| 参数写死在 `render` 里 | 拉不动，用户只能口头说「再大一点」 |
| 往页面里抄一份台子 / 为一页改 `lab.js` | 台子只有一份（2026-10-30 甲方定）：抄了就跟不上更新；要改台子改 `lab.js`，所有页面一起换 |
| 改骨架、把切换藏进侧栏 | 甲方定：切换都在顶条；左栏只放「看哪个」（界面 · 轮次 · 档），滑块在右栏（2026-10-30 甲方：滑块不常用，别占左栏主位） |
| 轮次做成段控、把界面塞进样本 | 甲方否过（2026-10-30）：轮次一多切起来麻烦、十几个界面把顶条挤爆；轮次 = 左栏一颗按钮点开清单，界面 = `PAGES` 一项一个、左栏竖排 |
| 几个界面共用一套档 / 只能一个个看 | 甲方要（2026-10-30）：每个界面有自己的一套档；`G` 全部界面并排，每格头上一排档号各切各的，切到哪档就是选哪档 |
| 顶条摆 agent 状态字、发送键混在顶条里 | 甲方否过（2026-10-30）：不要「agent 在等」；发送 = 右下角反差色悬浮键 |
| 到处贴组名、键位章、说明小字 | 甲方否过（2026-10-30）：冗余字太多；键位进悬停提示与 `?`，布局自己说明 |
| 交付后让用户手动拷 JSON 贴回来、每改一次重新 open | 甲方否过（2026-10-30）：服务开着（页面开着就一直在）、页面自己刷新；用户标注 → 右下角「发送」，你挂在 `/__lab/wait` 上等 |
| 交付完就结束、不挂 wait | 用户发了没人接。每轮回复结束前都要挂上 |
| 验完不关 ego 空间、不清测试状态、定稿了不关服务 | 甲方否过（2026-10-30）：开了什么就关什么，见 ⑨；服务另有闲置自关兜底 |
| 在宿主上直接 `node serve.mjs` | 全局规矩：长驻进程 / 监听端口 = 服务，一律进 Docker；用 `lab.sh` 起 |
| 写死端口 / 自己挑端口 | 甲方要（2026-10-30）：端口自动分、几个项目不撞；`lab.sh` 按项目路径定端口，被占才顺延，在跑的不动 |
| 换档 / 换样本做淡出淡入 | 甲方否过（2026-10-10）：中间黑一下，切换不干脆；比对靠的是瞬间换过去 |
| 让用户自己加减滑块 | 甲方否过：有哪些滑块是 agent 写页面时的判断，用户只管拉 |
| 记录与改动分两处、撤回做成按钮 / 提示条 | 甲方否过：一条记录时间线，撤回只走快捷键 |
