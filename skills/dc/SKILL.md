# dc —— 对照版

**用户说「给我几套看看」，交付物永远是一页能切档的对照 HTML，不是一段文字描述。**
看得见才判得准；文字描述的方案，用户只能凭想象判，判完还得重来一轮。

一句话流程：**先问清比什么 → `lab.sh <项目根> new <slug> <题目>` 搭页 → 定样本与第 0 档 → 写 ≥5 档完整方案 → 拍图自检 → 开一次页面 → 挂在 `/__lab/wait` 上等 → 有标注就改、回话、再等；没标注就是定了，按选档实装。**

**台子是现成的，你只写第 ② 段**：顶条、左右栏、标注、拼装、发送、自动刷新、和项目样式的隔离都在 `lab.js` / `lab.css` 里，任何项目里长相都一样——**不用检查台子、不用为台子截图**，验的只是你画的样本。

**两种稿，先判断用哪种**：
- **对比稿**（默认）：比一个模块 / 一块界面的几种做法，一格画一档。
- **交互稿**（③¾）：用户要「连起来用用看」——一整套页面（多个模块拼在一起、能跳转、能填、能提交、有反馈），判的是连续使用的体验。一档 = 一整套流程。
  用户说「做个交互稿 / 原型 / 走一遍流程」，或要判断的东西只有连着用才看得出（流程顺不顺、跳来跳去累不累、反馈到不到位），就用它；别拆成一个个模块各比各的。

页面长相（模板已做好，别改骨架）：**顶条在上，左栏看哪个，右栏滑块，右下角发送，其余全给生成的内容**——
- **顶条**（只放「怎么看」，不放说明字）：题目 · 交互 / 拼装 · 标注 · 钉住 ｜ 样本 · 单看 / 对照 / 全档 / 全部界面 · 比例 % · 明暗 · 记录 · 滑块 · 键位。
- **左栏**一座岛：**界面清单**（比几个界面才有，行尾是它当前选的档）→ **轮次**（多轮才有，一颗按钮点开全部，`R` / `⇧R`）→ **档清单**（选中那档就地展开论点 · 零件 · 代价）。
- **右栏**：**你按题目定的滑块**（轮次共用 + 选中档私有），用户只管拉、不让加减；不常用，`I` 收起。
- **右下角**：**反差色悬浮「发送」**（`⌘⏎`；有没发的标注带个数），上面一小摞是标注清单（发出去后顶上多一行进度）。agent 的回话只在**顶条中间露一句灰字**；改了哪儿看**左栏的「新」**。
- 舞台**默认一次只看一档**（数字键 / ← → 换档，**直接换、不淡出不入场**，只有首屏与 `P` 重播才逐格入场）；
  `C` 现状对选中，`A` 本界面全部档，`G` **全部界面并排**——每格头上一排档号，**各界面各切各的档**，切到哪档就是选了哪档。
- 「记录」= 交互动作、改动、标注、发送、agent 回话的一条时间线，**撤回不占界面**：⌘Z / ⇧⌘Z，撤回过的变灰。

## ① 开工前：三件事问清（能从代码查到的就去查，不问）

1. **比的是什么维度。** 「整块重做」和「只换按钮皮」是两种对照。先定哪些**可以变**、哪些**已经定了不许动**
   （已定的每一档都遵守 —— 否则档与档之间同时在变好几样东西，用户没法判是哪一样好）。
2. **痛点原话。** 用户圈出来的那几处就是验收标准。每一档都要回答那几处，答不上的档不出。
3. **样本从哪来。** 见 ②。

问法：一次一个问题，附上推荐答案（grilling 的问法）。已经能从代码 / CONTEXT / ADR 读到的，不问。

## ② 样本：按真实展示场景挑，≥3 条

- **样本的字段、动作、状态照项目里真的 schema / 组件抄**；数可以造，形状必须是真的。
  用户截图里那一条必须在样本里。
- **先想这一屏在真实使用里会以哪几种样子出现在用户面前**，每种挑一条，挑这一题最容易翻车的那几种（≥3 条），不是固定的稀 / 中 / 满：
  首次进入 / 空 · 日常（用户截图那条）· 重度（多、长、满、字超长）· 异常（出错、断网、没权限、已过期、被别人改了）· 过程中（加载、提交中、做了一半回来）……
  这一题比的是列表就该有「堆满了」，比的是表单就该有「填错了」，比的是首页就该有「新用户」与「老用户带着一堆事回来」。一个方案在最极端的两种场景下都站得住才算站得住。
- `from` 写**场景名**（「新用户」「月底对账」「断网」「上次没提交完」），不写「稀 / 中 / 满」——用户切样本时一眼知道自己在看哪种处境。
- 一条样本不够暴露某个毛病时（例如「挤了会怎样」），**补一条能暴露它的真样本**，别调参数假装。
- **第 0 档永远是现状**，照现行代码抄（类名、间距、墨阶照搬），不画成稻草人。单看时按 `0` 就是它；`C` 把现状与选中档并排细看。
- 样本一次只看一条（顶条段控 / `S` 切），换档、全档平铺都对着同一条样本——判的是档，不是样本。
- **样本 ≠ 界面**：场景是同一个界面的不同数据；工单页、事件页是不同的**界面**，各写一个 `PAGES` 项（见 4.2），别把界面塞进样本。

## ③ 档：≥5 套完整方案，每套一个论点

- **至少 5 档（不含现状），建议 6–8。** 少于 5 档没有选择余地；超过 10 档用户看不完。
- **每档是一套完整方案，不是一个零件。** 每档都把所有样本、所有部位画全。
- **比几个界面，每个界面各有自己的一套档**（档的设计各界面各不相同，第 0 档各是各的现状）；每个界面都守这一节的数量与论点要求。
- **每档一句论点**（它相信什么：「动作沉底」「状态是一条路」「值本身就是控件」），外加一排零件标签
  （`动作 底栏` `字段 窄标签列` …，一个参数一枚 chip，不用 `·` 串）和**一行代价**（它牺牲了什么，琥珀色）。
  写不出代价的档，要么是没想透，要么是稻草人。
- **每档都要有崭新的区别**（2026-11-25 甲方要），别交「同一个方案调了调间距 / 颜色」的几档。**主要拉开的是玩法**，其次是结构：
  - **玩法**（最要紧）：交互模型本身不同——就地展开还是推一层、点按还是滑动 / 拖、单条处理还是批量、表单填还是直接在值上改、先选后做还是先做后撤销、常驻还是按需长出来；
  - **结构**：信息怎么分组、主角是谁、放在哪、几栏、什么先看见；
  - **token 级**（少用）：token 不常变，默认所有档都用项目 token。只有用户点名要换视觉语言，或这一题本身就是比风格时，才让一两档在自己的 `css` 里给 `.root` 重新取角色值（圆角、字阶、密度、配色倾向、节奏），只在那一格生效，**不改项目的 token 文件**。
  发散轮 5+ 档里，至少一半在玩法上各不相同。两档之间说不出「它们是两种不同的想法」，就合成一档，再想一个新的。
- **收敛轮才钉维度**：用户挑了方向以后，新一轮把选中的部分钉成底子，档与档只变还没定的那一组维度；覆盖度优先——每个可变部位的每种做法至少在一档里出现一次，用户才能说「3 的路轨 + 1 的底栏」。
- **每档带完整的 motion**，不是静态图：入场、状态切换（展开 / 收起、选中、加载、成功 / 失败、出错）、悬停 / 按下反馈、退场——用 `on` 真做出来，点了就动。
  **全部有来有回**：怎么出来就怎么回去（从哪颗按钮长出来就缩回哪颗、滑上来就滑下去、淡入就淡出）；退场时旧节点留着播完再摘，别摘下重塞（里面的动画会停在第一帧）。
  时长、曲线取 token（`--t-*` / `--ease-*` / 弹簧），动法本身也可以是档与档的区别之一。只比一段过渡怎么动时，走 ⑤½ 动态稿。
- **要比的子组件开自己的界面，不塞进父界面的轮次**（2026-11-25 甲方：「新建入口」被做成父界面的 R8，跟别的轮混在一起）：比一个页面里的某个组件（入口按钮、筛选条、卡片头），新开一个 `PAGES` 项，写 `parent: "父界面名"`——
  左栏它缩进挂在父界面下面，有自己的轮次；父界面的档在那个位置写 `use("子组件名")`，每格都放子组件**当前选中**的那档；子组件的每一格自动套上父界面当前选中的那档，自己这一档嵌在原位（不用写 `frame`）。
  子组件里再有要比的子组件，同样再开一层。
- **一屏里两块各自独立、都要重画的部位（如「待办块」与「消息行」），拆成两个界面分开比**：一个部位一个 `PAGES` 项，每格照样画整屏，但只换自己那块、另一块钉在当前选定的那版（钉住的那块压到最小，让被比的部位首屏看得见）；`G` 并排各切各的档。别让一轮里每档同时换两块——用户喜欢 3 的这块、1 的那块时，捆绑档逼他整档二选一（2026-11-02 甲方：「行和领头明明是两个不同的设计方案，放在同一个 Round 一点都不方便看」）。
- **用户否过的方向**（项目记忆 / 口味清单里）可以放一档当对照，但代价行里写明「否过」。
- 守项目的设计系统：组件里只读 token 角色、不写裸色值（token 级的档在自己 `css` 顶上给角色重新取值，那里可以写值）；morii-design 的铁清单照走（一屏一颗主键、不许一个控件独占一行、选中不铺色块……）。

## ③¼ 设计纪律：每一档都守（不改项目 token 文件）

档与档比的是**方案**，不是谁更乱。下面是每档都要过的判据，不是样式模板——具体字号、间距从 token 的阶里挑（项目的，或这一档自己重新取值的那套），换了哪套取值判据都成立。

1. **先排重要度，再排版。** 动手前把这一屏的内容分三级：**主角**（用户来这一屏要看 / 要做的那一件）· **支撑**（帮着判断主角的）· **附注**（时间、来源、计数这类）。
   每一级只用一组「字号 + 字重 + 墨阶」，三级之间一眼分得开；一屏只有一个最重的（标题或主数）。正文统一一种，不在同级里混两种大小。
   附注靠降墨阶（`--ink-3` / `--ink-4`）退后，不靠缩到看不清。
2. **元素的生成逻辑要说得出来。** 同类东西同一种长相、同一条对齐线；相关的靠近、不相关的拉开——组内间距明显小于组间间距（约 1.5–2 倍差）。
   说不出「为什么这个在这儿」的元素，要么挪到它该在的组里，要么删。
3. **用满空间，留白是为了分组。** 不许单颗按钮独占一行（和同组控件或标题同行）；短内容不撑满整宽；两栏放得下就别竖排成一长条；首屏给主角。
   留白用来隔开组，不是用来填空——一大片空白旁边挤着一堆，比均匀铺开更糟。
4. **控件分主次。** 一屏一颗主键（反差色），其余用次级、文字或图标键；危险动作不跟主动作挨着、不同色。
5. **拍图时逐条过一遍**（⑥）：主角是不是第一眼看到的？三级分得开吗？有没有独占一行的单键、撑满整宽的短内容、说不出理由的元素？过不了的档先改再交。

## ③¾ 交互稿：一整套连续可用的页面

**比的是连起来用的体验**：用户从起点进来，点、填、跳、拉抽屉、提交、看反馈、返回，一路走下去。一档就是一整套方案（例如「列表推详情」对「就地展开」对「卡片翻面」），
档与档最好在**玩法**上不同（③），每档都完整可用、多个模块拼在一起，别只做被问到的那一块。

- **写法**：档上写 `flow`，不写 `render`（同一页可以混着有普通档）：
  ```js
  flow: {
    start: "home",                                   // 起始画面
    state: (spec) => ({ items: spec.items, … }),     // 这个起始场景的数据（样本 = 起始场景，见 ②）
    screens: { home: (s, nav, arg) => `…`, detail: (s, nav, id) => `…` },   // 画面：s 是数据，arg 是跳过来时带的
    sheets: { filter: (s, nav, arg) => `…` },        // 抽屉 / 底部弹层（可不写）
    on: { finish: (s, nav, el) => { …改 s…; nav.toast("已完成"); nav.back(); } },   // 动作：改数据、导航、提示
  }
  ```
- **画面里用属性接线**，不用自己写事件：`data-go="detail" data-arg="3"` 推进 · `data-back` 返回 · `data-tab="me"` 切底栏 · `data-sheet="filter"` 拉起抽屉 · `data-close` 收起 ·
  `data-act="finish"` 调 `on.finish` · `data-bind="draft"` 输入框回写 `s.draft`（写 `value="${s.draft}"`）· `data-toggle="hideDone"` 翻布尔。一个元素可以同时 `data-act` 与 `data-go`（先做动作再跳）。
  `nav` 还有 `go / back / tab / sheet / close / toast(字) / set(补丁) / after(毫秒, (s, nav) => …)`（模拟加载、提交、对方回复这类要等的事）。
- **每一下之后台子自动重画**：新旧画面就地比对，焦点、输入、滚动、CSS 过渡都保得住——状态变化（选中、展开、开关）写成 class 变化 + CSS 过渡，就会真的动起来。列表项带 `data-key` 能让增删认得准。
- **转场台子包了，全部有来有回**：推进从右滑入、返回原路滑出；切底栏淡入淡出；抽屉从下滑上、收起滑下（点遮罩也收）；提示从顶上落下再收回。画面内部的动效（展开、加载、成功）由你写，同样有来有回。
- **走到哪、数据成什么样都记着**：你改完页面自动刷新，用户还停在那一步、数据还在；`X` 回到起点与起始数据。
- **标注记得画面**：在详情页标的点只在详情页出现；清单里点那一条会走回那一步；发给你的标注带 `画面`。交互稿不开拼装（比的是体验，结构按标注改）。
- 外框默认像一台设备（圆角 + 描边影）：`tile` 写设备尺寸（手机 390×844、桌面 1280×800），页面 `CSS` 里可以盖 `.fl` 的圆角与底。
- 验收（⑥）：拍起点、走一遍主流程每一步各拍一张、再拍一张异常场景（`S` 换起始场景）；要验转场就在动作后 100–150ms 拍一张中间帧。

## ③½ 静态稿还是可交互稿

**默认是可交互稿**：模板默认只开「交互」，样本里的按钮、⋯ 菜单、编辑真能用（每一下记进「记录」）。
**「拼装」默认关**，用户要调顺序时自己开（顶条或 `M`）：**把一个小组件拖到另一个的前 / 后**——指针下那个零件边上亮一道线就是落点，松手**真改 DOM 顺序**
（同一组里换位，或挪进另一组；按钮、图标、标题字、标签各自能拖，控件整颗不拆），没落点就滑回原处；框右下角拉手改大小（吸 8px，Shift 不吸），双击归位，**⌥ 抓整组**（最近的具名零件）。
发给你的是人话：「「发送」挪到「取消」后面，从「顶栏」挪进「底栏」（现在顺序：取消 · 发送）」——照着改 `render` 的结构。比的是**行为**（状态、流转、点了之后怎样）时，必须写成真能点的：
按钮带 `data-act`、该开的菜单能开（`data-menu` + 轮次 `menu`）、该变的状态真变（轮次 `on`），别画一张图假装。

两颗都关 = **静态**：样本不响应指针，顶条长出「钉住」（常态 / 悬停 / 菜单开…），把某个状态摆出来（`A` 平铺时所有档同时摆）。
只比**外观**、或要截图对比某个瞬间时用它。钉住的状态在 `round.pins` + `round.pin(root, id, spec)` 里写。

**标注**（`F`，独立一颗，开着时盖过看法）：像在设计稿上留评论——指针下的组件有框与名牌，点哪儿就在哪儿落一枚带号的点，
贴着点长出一个小框写一句「这里要改什么」（⏎ 存、⇧⏎ 换行、Esc 放弃、点外面也存）。
**点绑在组件上，不是格内坐标**：记的是哪个组件（具名 / 路径 + 标签）和点在它里面的比例位置；组件一动（抽屉滑出、页签切换、拼装换位）点逐帧跟着走，
组件看不见（抽屉收起、页签切走）点就藏，滑出格子的剪掉；交给 agent 的也是组件（`组件 / 路径 / 原文 / html`），不是坐标。组件被 agent 改没了才落回记下的坐标。
点可以落在任何界面、任何档、任何样本上；右下角那一摞列出全部，点一条跳过去改 / 删。发出去的点变灰，agent 回话后消失。
想说整体的话，就点在格子空白处（认成「整格」）。
**参考**：写标注时 ⌘V 粘贴或把图 / 链接拖进小框（截图、竞品、设计稿、Dribbble / B 站 / YouTube 链接都行），带缩略图、可删。
链接自动转：直链图 / 视频直接取；网页取它的 `og:video` / `og:image`；视频再用 ffmpeg 抽一帧当封面。取不到小框里直接说原因，链接文字照样留在标注里。
都存在本机缓存（`~/.local/state/dc-lab/img/<项目>/`，不进仓库，30 天没用自动清），随标注一起发给你。
**你不用为标注写任何东西**：组件认法同拼装（没命名的按路径），给要跨档比的零件命名（`pa` / `part`）能让标注里的「组件」读得更明白。

## ④ 骨架：台子是共享的，页面只写第 ② 段

**台子只有一份**：本目录 `lab.js` + `lab.css`（顶条、左栏清单、右栏滑块、记录、标注、发送、舞台引擎），对照版服务在 `/__lab/lab.js` · `/__lab/lab.css` 下发。
**对照页只是一个壳**（`template.html`）：head 里 link 项目 token 与台子，body 里一段 `<script type="module">` 写第 ② 段，末尾 `labStart({ TOPIC, KEY, CSS, PAGES })`。
- 台子一改，所有开着的对照页自己刷新换上；**别往页面里抄台子，也别为一页改 `lab.js`**（要改台子就改这一份，所有页面一起受益）。
- 第 ② 段是自己的模块作用域，名字随便起，**不会和台子撞**；几个界面写在一页也不用手工包作用域。
- 页面**必须经对照版服务打开**（`lab.sh`，见 ⑦）；直接双击文件，台子加载不了。
- 壳**不带任何示例内容**——样本、样式、档全由你按题目现写，别从别的对照页抄内容过来（抄来的档会把这一题的判断带偏）。第 ② 段没填，页面会在舞台上报错并抛异常。

### 4.1 一条命令搭页

```bash
~/.claude/skills/dc/lab.sh <项目根> new <slug> <题目>   # 最后一行就是页面地址
```
它从 `template.html` 生成 `docs/lab/<slug>.html`：项目 token 自动找（常见位置，再全仓找 `tokens.css` / `Token.css`，同目录的 `fonts.css` 一起引；都没有就用台子的 `Token.css` 兜底）、
`TOPIC` / `KEY` 填好、服务起好。同名页已存在会报错不覆盖。之后只写第 ② 段；下面几样按需再改：

| 改什么 | 怎么改 |
|---|---|
| token | 自动找错了 / 要多引一份，就改头上的 `<link>`（只有变量会进样本；项目的类样式进不了影子，也碰不到台子） |
| 图标 | 全局 `ICON` 是台子自用的几枚；样本要用的从项目图标注册表抽出来，在第 ② 段 `Object.assign(ICON, { 名: "<path …/>" })` 补进去，**不手画**；缺的走 morii-icon |
| 项目自己的零件库 | 有（如 Coffice 的 `prop-kit.js`）就在 head 里台子前面再 `<script src>` 一行，第 ② 段直接用 |
| 页头注释 | 干什么 / 怎么跑 / 需要什么三行，写这一题的 |

### 4.2 填第 ② 段（只有这一段归你）

按这个顺序写：

1. **`TOPIC` / `KEY`**：题目名；`KEY` 是 localStorage 前缀，一题一个（`lab.<topic>.`）。
2. **`CSS`**：所有界面共用的样本样式。只进影子，只吃 token 与 `var(--p-*)`；**样本的样式绝不写进页面 `<style>`**（那是台子的）。
   样本最外层自己画面（底、圆角、影）；拼装时要让零件能拖出边，就给它加 `:host([data-mode~="build"]) .你的外框 { overflow: visible }`。
3. **`PAGES`**：比几个界面就写几项（只比一个就写一项）。每项 `{ name, specs, css, rounds }`：
   - `name`：左栏界面清单上的名字。
   - `specs`：这个界面的样本，≥3 条，按真实展示场景挑（见 ②；交互稿里是起始场景）。台子只读 `from`（顶条样本段控上的字）与 `note`（悬停提示）；其余字段照项目真 schema。
   - `css`：这个界面**所有轮**都用的样式（可不写）；只属于某一轮的写进那一轮的 `css`。
   - `parent`：**子组件**（可不写）。这个界面比的是父界面里的一个组件：左栏缩进挂在父界面下面；每格 = 父界面选中那档 + 这一档嵌在父界面 `use("本界面名")` 的位置。父界面的档里要写 `use`，不写就嵌不进去。
   - `frame`：**关联界面**（可不写，有 `parent` 时不用写）。同一屏拆成几个界面分开比（顶栏 / 正文 / 底栏）时，各档的 `render` 只画自己那一块，`frame(spec, 本块, { use })` 把整屏拼起来，
     别的块用 `use("顶栏")` 取——取的是那个界面**此刻选中的档**（连它拼装过的具名零件一起），用户在顶栏选了 1，底栏那页里看到的顶栏也是 1；样式自动带进来，样本按 `from` 对上。
     几块共用一个 `frame` 写法最省：`const frame = (me) => (spec, own, { use }) => …` 每个界面传自己占哪个位置。
   - `rounds`：这个界面的轮次，写法见下（`ROUNDS` 那张表就是每一轮的字段）。各界面的轮次互不相干，各自往下开。
   只比一个界面也可以不写 `PAGES`：`labStart({ TOPIC, KEY, CSS, SPECS, ROUNDS })`，台子当成一个界面。
   样本有交互状态（点过、填过、切过）时，把存状态的那张表交给台子清：`labStart({ …, reset: () => { for (const k in UI) delete UI[k]; } })`，顶条的「回到初始」与 `X` 会先调它再重画。
   台子给第 ② 段的全局只有五个：`ICON` · `ic(名, 尺寸)` · `pa(id, 名)` · `part(id, 名, html, cls?)` · `labStart(配置)`。
4. **每一轮**（`PAGES[i].rounds` 里一项）：下一轮在末尾追加、上一轮原样留着。字段：

| 字段 | 必填 | 是什么 |
|---|---|---|
| `name` | 是 | 轮名，顶条上切轮次用 |
| `tile` | 是 | `{ w, h }` 每格多大：数字（px），或一个共用参数的 key（格子跟着那条滑块变） |
| `list` | 是 | 档：`{ name, thesis, parts: [[键, 值], …], cost, css, params, render(spec) }`；第一轮第 0 档 = 现状 |
| `css` | 否 | 这一轮各档共用的样式（夹在界面 `css` 与档 `css` 之间）。**只给这一轮用的样式放这里，别堆进界面的 `css`**：界面 `css` 算进每一轮的指纹，改一处整个界面的轮全标「新」 |
| `uses` | 否 | `[fn, …]`：档的 `render` / `on` 调到的 helper。指纹只看得到档上函数自己的源码，helper 改了要标「新」就列进来 |
| `params` | 否 | 共用滑块，见下 |
| `menu` | 否 | `(spec, btn) => [{ label, danger }]`：样本里带 `data-menu` 的按钮弹出的菜单 |
| `on` | 否 | `(act, { root, spec, btn, log }) => void`：带 `data-act` 的元素（按钮或整行）被点时的真行为（改名、换状态…）；不写就只记一笔 |
| `pins` + `pin` | 否 | 静态看法下可钉住的状态 `[[id, 名], …]`，`pin(root, id, spec)` 把影子里的样本摆成那样（可调台子的 `openMenu(root, btn)`） |
| `figure` | 否 | `(v, d, box) => HTML`：记录弹层顶上的示意图，`v` 当前值、`d` 默认值；`.fig-ghost` 画默认虚影、`.fig-face` 画当前实面 |

### 4.3 `render` 怎么写

- `render(spec, { use })` 返回这一档在这条样本上的 HTML，台子包进影子里的 `.root`（`use` 见 4.2 的 `frame`；不拆界面就用不到）。
- **拼装不用你套壳**：台子自动认到每一个小组件。没命名的零件按「样本 + 画出来时的 DOM 路径」记，只在那条样本上生效、名字取文字 / `aria-label`。
- **给要跨档比的零件命名**（主键、标题、状态章、动作栏这类用户会说「把 3 的 X 挪到 1」的）：
  单个元素直接写属性 `<button ${pa("send", "发送")}>`；一组用 `part(id, 名, html, cls?)` 套壳（⌥ 拖抓的就是它）。
  `id` 跨档同名，命了名的换位换样本也跟着走、被别的界面 `use()` 时也照样摆，记录与发给你的人话里也叫这个名。
  拉过大小的零件宽高直接写在它身上（套壳的组则内容撑满壳），所以零件内容要能跟着宽高走（弹性排布、别写死尺寸）。
- **外框自己画**：台子只给一个空的 `.root`，样本的面（底、圆角、影、`overflow`）由 `render` 返回的最外层画。
- 能点的写成能点的：动作按钮带 `data-act="动作名"`，菜单按钮带 `data-menu`（见 ③½）。
- **手机外面发生的事不画进屏里**（碰一张标签、来网断网、来电、对方回了消息这类模拟触发）：给那颗按钮加 `data-ext`（值是键上的字，空就用按钮自己的字）。
  台子把它藏起来，在格子右边外侧挂一排虚线边的触发键，点它 = 点那颗按钮（照常进 `on` 与记录）；样本重画了跟着换，有触发键时每列自动让出宽度。
  别把模拟触发做成屏里的一颗胶囊——用户分不清哪颗是界面、哪颗是在模拟现实（2026-11-04 甲方）。正在退场的旧帧要设 `inert`，它里面的触发键不挂。
- 只用 token、`var(--p-*)` 与 `ic()`；档自己的样式写进它的 `css` 字段。

### 4.4 滑块由你决定（用户只管拉，不让用户自己加减）

- 只放会左右判断的那几条，一轮 **2–6 条**，不是把所有 CSS 值都摆出来。
- 写法 `{ key, label, min, max, step, tick, def, unit }` → 影子里读 `var(--p-<key>)`。
  所有档都受影响、要公平比较的放**轮次** `params`（右栏上标「共用」）；只有某一档才有的旋钮放**那一档**的 `params`（选中那档时才出现）。
- 范围覆盖「明显太小」到「明显太大」，`def` = 你推荐的值；`tick` 管画几道刻度，别让刻度糊成一片。
- 拉刻度轨只改变量不重画（开着的菜单不会被冲掉）；每一下都进记录，⌘Z 可撤回。

## ⑦ 交付：起服务、开一次、挂着等

对照页由**对照版服务**托管（`serve.mjs`，零依赖 Node；**本机进程**——它是本机开发工具，不算后端，不进 Docker；`lab.sh` 管端口、pid、日志）。

1. **起服务**（`lab.sh new` 搭页时已经起好；之后再要地址就跑这条），端口自动分（幂等：已经在跑就只报地址；同一项目每次同一个端口，被别人占了就往后找，几个项目同时开不撞）：
   ```bash
   ~/.claude/skills/dc/lab.sh <项目根>     # 最后一行就是 <地址>，如 http://127.0.0.1:47520
   ```
   下面的 `<地址>` 都是它；忘了就再跑一次，便宜。**别自己挑端口、别直接 `node serve.mjs`**——端口一变，页面的源跟着变，存的选档、标注全丢。
   页面在前台开着就一直在；关了页面或切到后台，15 分钟后它自己关。页面每 1.5 秒（标签在后台时 5 秒）来问一次 `/__lab/state`，对这一页的版本、取 agent 的回话，不挂长连；服务重启期间问不到就下一轮再问，接上时版本对不上就补一次刷新——你不用叫用户手动刷新（自带台子的老式对照页仍走 `/__lab/events` 长连，服务每 20 秒给它一声心跳）；用户说「没刷新 / 回话没出来」先 `curl <地址>/__lab/ping` 看 `pages` 里有没有那一页。改过 `serve.mjs`：`lab.sh <项目根> stop && lab.sh <项目根>`（端口不变）。服务起不来 / 莫名关了：日志在 `~/.local/state/dc-lab/<项目名>.log`。
2. **开一次**：`/usr/bin/open <地址>/docs/lab/<topic>.html`（裸 `open` 在 cmux 里可能被替身接走）。
   之后**不再 open**——你每改一次文件，那页自己刷新；用户已经开着就跳过这步。
3. **挂着等**（`run_in_background`，同一时间只挂一个）：
   ```bash
   curl -s '<地址>/__lab/wait?page=/docs/lab/<topic>.html'
   ```
   **一定带 `?page=`**：同一项目常有几个会话各开各的对照页、共用一个服务，不带就把别人那页的批也截走（2026-11-02 撞过）。
   用户点右下角「发送」（或 ⌘⏎），curl 带着一批 JSON 退出，你被唤醒。服务重启时 curl 会空手退出（exit 52），重新挂上就行。
   **wait 一直挂着，包括你改的时候**：取到一批，**先在后台重新挂上 wait，再动手改**。用户常在你改的途中想起要补一句，挂着的 wait 会把补充当场送到你手上（中途被唤醒）；
   不挂的话补充只能排队，等你改完、页面刷新成新版才送到——它是对着旧版写的，对不上。页面托盘顶上那行（「agent 在改第几批」「补充的排着」「agent 没在听」）读的就是这个状态。
   **wait 回来的是 `{"关了": …}`** = 没人看、服务自己关了：**别重起、别再挂**（否则每 15 分钟起一次关一次、白唤醒你一次），终端里说一句「对照页闲置已关，要接着看叫我」；用户回来再 `lab.sh` 起、挂上，页面刷新就接上。
4. 回复里：一张表列出各档（`# · 名 · 一句话`；多个界面就每个界面一张），写明第 0 档是现状、怎么用（`F` 标注 · `G` 全部界面各切各的档 · `⌘⏎` 发送；要挪零件开「拼装」），哪些已验、哪些没验。
   最后一行：**标注要改的地方、每个界面切到想要的档，点右下角「发送」，我在等。**

### ⑦½ 收到一批之后

一批 JSON 长这样（字段名就是中文）：`页 · 题目 · 意思 · 在看`（界面 · 轮 · 档 · 样本）· `选档`（每个界面当前选的档）·
`标注[]`（`号 · 界面 · 档 · 样本 · 组件 · 具名 · 路径 · 原文 · html · 要改 · 图 · 视频 · 链接`——`图` 是参考图（视频给的是封面）的本机路径，**有就先用 Read 打开看**，「按这张图的…」说的就是它；`视频` 是原片路径，要看节奏就用 ffmpeg 多抽几帧再看；`链接` 是用户贴的原链接）· `参数`（改过的滑块，带默认值）· `布局`（每档一串人话：谁挪到谁前 / 后、现在的顺序、改过的宽高）。
`选档 / 参数 / 布局` 是**当前全量**，不是增量；`选档` 就是用户的挑选——切到哪档就是要哪档。

**先看 `意思`**：
- **补充**（「补充：…合进还没回话的那几批」，或改的途中又醒来拿到的新一批）：合进手上这一轮一起改，同一个组件的要求以后发的为准；**一句回话答完所有批**。
  台子按批号清点：回话答的是这一页已经交给你的全部批，排着还没送到你手上的不算，所以合着答不会漏、也不会误清。
- **空 = 定了，去实装**：按 `选档` 把每个界面选中的那档落进项目真代码（选第 0 档的界面保持现状），`参数` / `布局` 有改动的一并照做。不再开新一轮、不追问「确定吗」；
  实装完回话一句做了什么、改了哪些文件，然后按 ⑨ 收尾（停 wait、关服务）。
- **有标注 = 接着改**：走下面 1–5。

1. 逐条照 `要改` 改 ② 段（`路径` + `原文` + `html` 足够在 `render` 里定位；`具名` 有值就搜 `data-part`）。改不了 / 有疑问的那条，别硬改，回话里说。
   `布局` = 用户亲手换过的顺序（「A 挪到 B 后面，从 X 挪进 Y；现在顺序：…」）与拉过的宽高：**照着改 `render` 的结构**，把它写进代码。
   不用管页面上的拼装：你回话时台子会把那批发出去、之后没再动过的拼装收起，改进代码不会重放两遍；不照做就在回话里说为什么。
   **别靠改档名、换零件 id 去躲旧拼装**：拼装按档的位置（界面.轮.档）存，不按名字。
2. 改完**先拍图自检**（⑥），页面已经自己刷新了。
3. **回话：一句话**（≤ 40 字），只在页面顶条中间露一行灰字（悬停看全文），发出去的那批点与拼装随之收起。用户基本不读它——
   说这一轮做成了什么就够（「R3 开了 4 档，都按选的居中打底；3 号没动，见终端」），详细的、要用户拍板的写在终端回复里。不写列表、不分段。
   ```bash
   curl -s --data-binary @- '<地址>/__lab/say?page=/docs/lab/<topic>.html' <<'EOF'
   <一句：做成了什么>
   EOF
   ```
   `?page=` 点名回给哪一页（服务重启过就认不出最后一批是哪页了，不带会丢）；页面按批号清点：这一页已经交给你的批都收起，排着没送到的补充不动。
   开了新一轮的，用户那页自己落到最新一轮（没见过的轮直接跳过去），不用叫用户去翻轮次按钮。
4. **确认 wait 还挂着**（取到这批时已经重挂了；改的途中又被补充叫醒过，就再挂一次），然后结束这一轮回复（终端里也给一句同样的话）。用户在终端直接打字也照常处理，挂着的 wait 不受影响。
5. 用户说「就这样」或各界面的 `选档` 稳定了，按 ⑧ 开下一轮，或按 ⑨ 收尾。

丢了一批（wait 被杀、会话断了）：`curl -s '<地址>/__lab/last?page=/docs/lab/<topic>.html'` 取回这一页最后交出去的那批。
截到了别人那页的批（`页` 不是你的）：别动它，去掉 `batch` / `at` 两个字段原样 POST 回 `<地址>/__lab/send`，它回到队列等主人取。
用户手里只有文件、没法起服务时：先 `lab.sh` 把服务起来再给地址——台子不在页面里，`file://` 打不开。

## ⑧ 下一轮

- 用户挑完，**同一页开下一轮**（那个界面的 `rounds` 加一项，左栏轮次按钮 / `R` 切换），上一轮原样留着当判据记录。页面自己刷新，不用再 open。
- 新一轮把选中的部分**钉成底子**，只变还没定的维度，仍然 ≥4 档（收敛轮可以少于 5）。
- 每定下一条，当场写进项目的 CONTEXT.md（术语）或 ADR（难反悔、有取舍的决定）—— 项目用 domain-modeling 时照它的格式。

## ⑨ 收尾：开了什么就关什么

**每轮回复结束前**（不只是最后一轮）过一遍，开着的东西都是用户的负担——用户的浏览器里攒一堆 agent 开的标签，比没做还烦：
1. **ego 验收空间**：拍完图当场 `await task.finish({ keep: [] })`，一轮一关，不攒到最后；中途开的临时标签随手 `page.close()`。
2. **测试状态**：ego 的档案可能就是用户自己的浏览器 —— 截图只走 `?shot`（⑥），不碰 localStorage；**不许清 / 删这一题的键**，用户的标注与选档在里面（VERIFY 6）。
3. **wait 只挂一个、一直挂着**：取到一批后立刻重挂（上一个已经带着那批退出了）；重挂之前确认上一个已经退出（收到一批、或服务重启 exit 52；收到 `关了` 就不再挂）；别同时挂两个，否则一批会被旧的那个抢走。

**用户说定稿 / 不用了 / 先这样**：
4. 停掉挂着的 wait（`TaskStop` 那条后台任务）。
5. 关服务：`~/.claude/skills/dc/lab.sh <项目根> stop`（不关它也会没人看 15 分钟后自己关，但用户明说完了就当场关）。
6. 回复里一句话交代：服务关了、wait 停了、浏览器里没留东西。

## 反模式（见一个删一个）

| 反模式 | 为什么错 |
|---|---|
| 用文字描述 N 套方案让用户选 | 用户只能凭想象判，判完还要再做一遍 |
| 第 0 档画成稻草人 | 对照失去意义；照现行代码抄 |
| 只有一两条样本，全是「日常」 | 极端场景（空、堆满、出错、做了一半）才暴露毛病 |
| 档与档同时变好几样 | 判不出是哪一样好 |
| 两块独立部位捆在同一轮、每档一起换 | 甲方否过（2026-11-02）：喜欢这档的上半、那档的下半时没法挑；一个部位拆一个界面，另一块钉住 |
| 每档只画一个零件 | 零件好看不等于整体成立 |
| 代价行空着 | 没有代价的方案是没想透 |
| 没拍图就交 | 折行、截断、错位只有眼睛看得出 |
| 下一轮另开新页、旧轮删掉 | 判据记录丢了，下次又问一遍 |
| 档的样式写进页面 `<style>` | 漏出影子、台子与样本互相污染，判的不是档本身 |
| 比行为却只画静态图 | 用户要点了才知道好不好；能点的就做成能点 |
| 参数写死在 `render` 里 | 拉不动，用户只能口头说「再大一点」 |
| 往页面里抄一份台子 / 为一页改 `lab.js` | 台子只有一份（2026-10-30 甲方定）：抄了就跟不上更新；要改台子改 `lab.js`，所有页面一起换 |
| 改骨架、把切换藏进侧栏 | 甲方定：切换都在顶条；左栏只放「看哪个」（界面 · 轮次 · 档），滑块在右栏（2026-10-30 甲方：滑块不常用，别占左栏主位） |
| 轮次做成段控、把界面塞进样本 | 甲方否过（2026-10-30）：轮次一多切起来麻烦、十几个界面把顶条挤爆；轮次 = 左栏一颗按钮点开清单，界面 = `PAGES` 一项一个、左栏竖排 |
| 几个界面共用一套档 / 只能一个个看 | 甲方要（2026-10-30）：每个界面有自己的一套档；`G` 全部界面并排，每格头上一排档号各切各的，切到哪档就是选哪档 |
| 回话写成长文 / 右下角弹回话卡片、「这次改了」卡片 | 甲方否过（2026-11-25）：没人看，还压舞台。回话一句，露在顶条中间；改了哪儿只在左栏挂「新」 |
| 顶条摆 agent 状态字、发送键混在顶条里 | 甲方否过（2026-10-30）：不要「agent 在等」；发送 = 右下角反差色悬浮键 |
| 到处贴组名、键位章、说明小字 | 甲方否过（2026-10-30）：冗余字太多；键位进悬停提示与 `?`，布局自己说明 |
| 交付后让用户手动拷 JSON 贴回来、每改一次重新 open | 甲方否过（2026-10-30）：服务开着（页面开着就一直在）、页面自己刷新；用户标注 → 右下角「发送」，你挂在 `/__lab/wait` 上等 |
| 交付完就结束、不挂 wait | 用户发了没人接。每轮回复结束前都要挂上 |
| 验完不关 ego 空间、不清测试状态、定稿了不关服务 | 甲方否过（2026-10-30）：开了什么就关什么，见 ⑨；服务另有闲置自关兜底 |
| 用户要「连起来用用看」，交的是一个个模块各比各的 | 甲方要（2026-11-25）：交互稿 = 一整套能连续用的页面，多个模块拼在一起，跳转、抽屉、表单、反馈都真能走（③¾） |
| 样本写成「稀 / 中 / 满」三个字 | 甲方要（2026-11-25）：按真实展示场景挑、按场景起名（新用户、断网、做了一半回来…） |
| 几档只差间距 / 颜色 / 圆角，或交一页静态图 | 甲方要（2026-11-25）：每档是一种新想法，主要拉开玩法、其次结构，token 少动；每档带完整、有来有回的 motion |
| 比一个子组件就往父界面里加一轮 | 2026-11-25 甲方：「新建入口」成了父界面的 R8，跟别的轮混着。子组件开自己的界面（`parent`），父界面的档里 `use()` 它 |
| 测试时往页面存储里写主题、选档、看法（`localStorage.setItem('lab.…')`） | 2026-11-25 踩过：ego 就是用户自己的浏览器，agent 测试设的「亮」留在了用户那边，打开不是系统主题。截图一律走 `?shot`（状态只在内存）；要测交互就开副本页（换 `KEY`，见 VERIFY） |
| 拼装做成自由位移 `{x, y}` | 2026-11-25 换掉：agent 读不懂「往右 37px」是换位还是对齐，拼装形同虚设。拼装 = 真换 DOM 顺序 + 一句人话 |
| 「新」按「离开那个界面」才算看过 | 2026-11-25 查出：agent 每改一次就刷新，用户一直停在同一界面，看过的改动一轮轮叠回「新」。按「界面 · 轮」在台上停够才算看过 |
| 台子读项目 token / 跟项目共用类名 | 2026-11-25 查出：Hrige / Morii 缺 `--chin-glass`、`.seg` `.badge` 撞名，台子透明错位。台子钉 `Token.css` + 项目样式进低层 + 台子元素先退回默认 |
| 收到没标注的一批还追问 / 再开一轮 | 甲方要（2026-11-25）：没有意见 = 定了，按选档实装 |
| 取到一批先改完再挂 wait | 2026-11-25 甲方：中途补充的要等 agent 改完才送到，对着旧版、对不上。取到就先重挂，补充改的途中就到，合进同一轮 |
| 闲置判定把挂着的 agent、后台标签算「在用」 | 2026-11-25 查出：会话常挂几天，服务从没自关过一次（42 次全靠 reaper 闲 2 小时强停）。只认看得见的页面与排队的批 |
| 盯文件用 `fs.watch`、长连不带心跳 | 2026-11-01 踩过（服务当时在容器里）：挂载上文件事件改十几次只响一次，长连被端口转发悄悄掐掉、页面以为还连着——刷新与回话都到不了。轮询 mtime + 心跳 + 重连对版本 |
| 直接 `node serve.mjs` / 自己 nohup / 塞回 Docker | 用 `lab.sh` 起：它管端口、pid、日志、幂等。对照版服务是本机开发工具，按全局 CLAUDE.md 不进 Docker（2026-11-25 从 Docker 挪出：每项目一个容器、只停不删，越攒越多） |
| 写死端口 / 自己挑端口 | 甲方要（2026-10-30）：端口自动分、几个项目不撞；`lab.sh` 按项目路径定端口，被占才顺延，在跑的不动 |
| 照 `布局` 改了 render，页面上的拼装还在 | 2026-11-17 踩过：拼装又重放在新结构上，被推出框外、整块空了。台子已在回话时收起发出去的拼装；新写台子的存储也照这条——交给 agent 的东西，回话后归 agent |
| 换档 / 换样本做淡出淡入 | 甲方否过（2026-10-10）：中间黑一下，切换不干脆；比对靠的是瞬间换过去 |
| 让用户自己加减滑块 | 甲方否过：有哪些滑块是 agent 写页面时的判断，用户只管拉 |
| 记录与改动分两处、撤回做成按钮 / 提示条 | 甲方否过：一条记录时间线，撤回只走快捷键 |
