# Morii Icon — 图标动效

图标级动效规范。上位法是 `~/.claude/skills/morii-design/MOTION.md`（频次闸、曲线、时长、可打断、时间线编排）——**这里只写图标特有的部分，不重复上位法**。

**§2 的技法片段是构造演示，不是可粘贴的成品**（同 `SKILL.md` §4 对造型技法的态度）：学它的构造方式——由什么驱动、分几拍、哪个量随 `--p` 变——然后为**这个**图标重新写一遍。整段照抄只会让所有图标动得一模一样。

## 五条根（破一条就出家族）

1. **默认不动。** 图标是界面里出现最密的元素，一天被看几百次——按频次闸，它的默认状态就是**静止**。动效必须被「挣」出来（§1），不是默认赠品。
2. **在档位内动。** 实心档靠 **缩放 / 裁切 / 挖空显隐 / 共享部件位移**，中间帧始终是实心块面（途中变成空心框 = 破家族）；线性档靠 **描边长度 / 端点 / 角度 / 分段显隐**，中间帧描边宽度**恒定不变**（忽粗忽细、抖线、扭曲 = 破家族）。两档共同的底线：**中间帧必须仍是一个成立的图形**，不能路过一个说不清是什么的形状。
3. **绕 (12,12) 动。** 一切 transform 的原点就是 §2 定的视觉质心（24 网格上的 12,12）。缩放不许让质心漂移，旋转不许让图标偏出光学中心。
   **只给会动的那几个件设 `transform-box: view-box; transform-origin: 12px 12px`，禁止写成 `.icon *`。** SVG2 里 `transform` **属性**就是 CSS `transform` 属性，全局套 `transform-origin` 会和元素自带的 `transform="rotate(a cx cy)"` 叠加，把部件甩到画格外（放大镜手柄会飞成一个孤点）。带旋转的静态部件，**把旋转烘进路径坐标**，别留 transform 属性。
   绕 (12,12) 转的字形，其**自身质心也必须在 (12,12)**——三角形/箭头这类不对称形状要先算重心再摆放，否则旋转过程会「摆头」。
4. **一个进度值 `--p` 驱动。** 每个图标动效都是 `p ∈ [0,1]` 的纯函数：`p` 正着走是入，倒着走是出。连点两下的开关必须**从当前值反向**，不能跳回 0 重放。
5. **一套动效尺度，全集共用。** 和「一套圆角阶梯 / 一套描边阶梯」同理：全集只用 `--t-press / --t-fast / --t-med` 三档和 `--ez`，**不许某个图标自带一条独家曲线**。一排图标动起来必须像一个套件。

## 1. 什么时候允许动（只有这五处）

| 场景 | 目的 | 时长 | 说明 |
|---|---|---|---|
| **状态切换** play↔pause · check on/off · like · mute · chevron 展开 | 状态可读 | `--t-fast` | 唯一真正高价值的图标动效 |
| **档位切换** 未选中线性 ↔ 选中实心（`SKILL.md` §A-1） | 状态可读 | `--t-rank`（自己一档，见 §2 D-3） | **做法只有一个**：§2 D-3 灌满，全产品一处实现。**频次闸在这里不判死**：动的不是装饰，是状态本身 —— 换档这件事无论如何都会发生，动效只决定它是硬切还是有个交代 |
| **按压反馈** | 反馈 | `--t-press` | **由按钮承担**（`scale(var(--press))` 在按钮上），图标自己不另写 |
| **结果确认** 一次性打勾 / 完成 | 反馈 | `--t-med` | 罕见层级，可以画一笔（§2C） |
| **空态插画入场** | 防跳变 | ≤500ms | 罕见层级，允许错峰 |
| **加载环** | 状态可读 | 循环 | **全系统唯一允许循环的动效**；规格随上位法：16–20px · 描边 1.5–2 · 中性 `--ink-4` · 无轨道 · 弧长 25–35% · 匀速 1s · 不带文字 |

**不允许**：hover 摇摆 / 弹跳 · tab 图标每次切换都转一圈 · 列表图标逐个错峰飞入（一天看几十次）· 无交互的 idle 呼吸 · 「因为好看」。
拟物会动的小物件请走 `morii-charm`（那是另一种东西：CSS 堆叠的小物 + 一个循环生命体征），不要把 morii-icon 掰成它。

## 2. 技法（按图标构造方式选）

> **顺序是：内容气质 → 风格档位（`SKILL.md` §A）→ 从该档位的技法清单里挑。** 动效永远是最后一步，**不构成改造型或换档位的理由**——需要空心框才好裁切？换技法。这个图标"画成线更好做 draw-on"？换技法，因为单独破例会毁掉整套的一致性（那是 §A 里最不能破的一条）。
>
> | 档位 | 顺手的技法 | 不要硬套 |
> |---|---|---|
> | **实心 Solid** | A 质量弹入 · B 挖空错峰 · D-1 共享部件 · E 进度裁切 · F 色阶迁移 | **C 一笔画出**——实心块面没有"一笔"，硬拆成描边就破了档位（唯一例外：本来就是粗描边的勾/环/弧）|
> | **线性 Line** | **C 一笔画出（天生适配，首选）** · D-1 共享部件 · 端点/角度位移 · F 色阶迁移 | **E 进度裁切**（裁一条描边会露出断口）· B 挖空（线性档没有可挖的块面，改用描边分段显隐）|
> | 两档通用 | **D-3 换档灌满（线性↔实心的唯一标准做法）** · D-2 交叉淡化 · 按压缩放 · 加载环 | — |
>
> 反面清单（出现即返工）：为了 draw-on 把实心物体拆成描边 · 为了 progress-clip 把物体画成空心框 · 为了 morph 把两个字形都简化成线 · 为了留出动画空间把主体缩小画矮 · **为了某个技法让一个图标脱离全集档位**。

### A. 质量弹入 mass-pop（实心字形出现）
```css
.icon-in { transform: scale(.92); opacity: 0;
           transition: transform var(--t-fast) var(--ez), opacity var(--t-fast) var(--ez); }
.icon-in[data-shown] { transform: none; opacity: 1; }
```
永不 `scale(0)`（root 2 + 上位法）。起点 `.9–.95` 之间，低于 .88 就开始像「凭空冒出」。

### B. 挖空显隐 knockout-reveal（物体类：日历格、便签文字线、电量档）
**壳不动，只让内部细节出现**——这正是 root 4「简单外形 + 内部细节」的动态版。内部子路径按 §2 的公式位置错峰：
```css
.detail { opacity: 0; transition: opacity var(--t-fast) var(--ez) calc(var(--beat) * var(--i)); }
[data-shown] .detail { opacity: 1; }
```
`--i` 用网格序号（第几行/第几个点）派生，**不许随机**。

### C. 一笔画出 draw-on（线性档的主力；实心档仅限本就是粗圆描边的字形：对勾、搜索环、wifi 弧）
给路径加 `pathLength="1"`，长度就被归一化成 1——不用 JS 量长度，纯 CSS 就能用 `--p` 驱动：
```svg
<path pathLength="1" style="stroke-dasharray:1; stroke-dashoffset:calc(1 - var(--p));"
      fill="none" stroke="currentColor" stroke-width="3.6" stroke-linecap="round"/>
```
```css
.check { --p: 0; transition: --p var(--t-med) var(--ez); }   /* 需 @property 注册 --p 为 <number> */
.check[data-on] { --p: 1; }
```
无 `@property` 时退回 `stroke-dashoffset` 直接过渡（值 1 → 0）。
**实心档的块面图标不许为此改画成描边**——它没有「一笔」可画。线性档则相反：draw-on 是它最自然的入场，全集共用同一条描边宽即可。

### D. 双态形变 morph（两个状态之间）
优先级从高到低：
1. **共享部件位移**（最佳，永远实心）——两个字形由同一批基础部件构成，只动部件的位置/尺寸/角度：`+` → `×` 是整体转 45°；chevron 展开是转 180°。这也正好复用 root 5 的「共享部件」。
   **多部件必须分拍，不能同时位移 + 旋转**——同时做，中间帧会退化成第三个（错误的）字形：汉堡→X 若一边平移一边转，`p=.5` 处读成一个 `>`，整条时间线中间全是废帧。正确是两拍：
   ```css
   /* t1 合拢 p∈[0,.5]，t2 旋转 p∈[.5,1] —— 中间帧是干净的「一条线」 */
   .bar{--t1:clamp(0,var(--p) * 2,1);--t2:clamp(0,(var(--p) - .5) * 2,1)}
   .bar-top{transform:translateY(calc(var(--t1) * 5.6px)) rotate(calc(var(--t2) * 45deg))}
   .bar-mid{opacity:calc(1 - var(--t1));transform:scaleX(calc(1 - var(--t1)))}
   ```
   通则：**一个中间帧里只允许一种自由度在变**。两种同时变，十有八九会路过一个说不出是什么的形状。
2. **交叉淡化 + 微缩放**（两个字形骨架不同时）：旧的 `scale(1)→(.9)` 淡出、新的 `(.9)→(1)` 淡入，共用 `--t-fast`，两者都绕 (12,12)。
   **重叠窗口要窄**：两条 opacity 曲线的交叠控制在进度的 **≤20%**（如旧的 `clamp(0,(.55−p)·2.4,1)`、新的 `clamp(0,(p−.45)·2.4,1)`），否则中间帧就是明晃晃的双重曝光。掩饰用的 `blur` 峰值 **≤0.8px**（`calc(4p(1−p) · .6px)`）——再大就从「一次形变」糊成「一团东西」。
3. **换档灌满 rank-fill**（同一只字形的线性 ↔ 实心，`SKILL.md` §A-1）——**这是换档的唯一标准做法**，全产品一处实现，不许一个表面一个写法。它不是 D-2 的一个变体：D-2 是两个不同字形在互换，这里是**同一个形从描边变成实体**，所以做法也不同 —— 不淡替，而是**灌满**。

   两档同时挂在一个 svg 里。**实心档始终不透明**，露出多少由裁切说 —— 它是从底边被灌上来的，不是淡进来的；描边垫在下面，**押后几拍再退**，并和灌满**同时收尾**：
   ```css
   .rk { transform-origin: 12px 12px; transform: scale(.98) }   /* .98 是 §1 安全边 */
   .ic.pair > .sd { clip-path: inset(100% 0 0 0) }
   /* → 选中：灌满走 --t-rank；描边押后四拍，退的时长补足同一条时间线 */
   .ic.pair:not(.is-line) > .sd { clip-path: inset(0 0 0 0);
     transition: clip-path var(--t-rank) var(--ez) }
   .ic.pair:not(.is-line) > .ln { opacity: 0;
     transition: opacity calc(var(--t-rank) - var(--beat) * 4) var(--ez) calc(var(--beat) * 4) }
   /* → 取消选中：反着走 ×0.7；这一程描边不押后，实心退到哪它就得跟到哪 */
   .ic.pair.is-line > .sd { transition: clip-path calc(var(--t-rank) * .7) var(--ez) }
   .ic.pair.is-line > .ln { transition: opacity calc(var(--t-rank) * .7) var(--ez) }
   ```
   四条要害，破哪一条都会被一眼看出来：
   - **描边绝不能先于填充退完。** 早退就有一段时间上半截既没描边也没填充，那道空档看着就是「断层」——这是这个技法唯一的翻车方式。押后的拍数是它唯一的调节量，两条线必须同时收尾。
   - **两条时间线共用一条曲线。** 一条 ease-out 一条匀速，灌到八成时描边才退到四成，读作「描边掉队」。
   - **时长要故意越出常规梯子。** 其余动效都是「闪一下告诉你变了」，这一个是要让人看见灌的过程 —— 走 220ms 就只剩一次闪，等于没有。它只作用在一枚 15–20px 的字形上、不搬动任何版面，所以「界面动效 <300ms」那条不适用（那条管的是位移与面积）。**注册成一个 token**（如 `--t-rank`），写成常规档的倍数而不是裸值：全站动效仍然只有一把梯子，这只是它的延长档，且**改一个数 = 全站换档速度**。
   - **安全边不能留在 `transform` 属性上**：SVG2 里 CSS `transform` 会把属性整个盖掉，两处写就只剩一处生效，图标会悄悄涨到顶格。

   另外两件别做：**别加 blur**（两档轮廓本来就重合，糊一下只会脏）；**别做成两个组件各自渲染再 `<Transition>`**——那是两个 DOM 节点在替换，替换瞬间会闪，动效也就跑到调用点去了，违反 §4。
   `prefers-reduced-motion` 由全局那条 `transition-duration` 兜底，不必另写降级分支。
   **退路**：只有当两档轮廓真的对不齐才退回 D-2 的交叉淡替 —— 而这不该发生，§A-1 要求两档同名同形。

4. **直接 `d` 插值**：跨浏览器不稳（要求命令数与顺序完全一致），只在两条路径本就是同骨架时用，且必须实测。

### E. 进度裁切 progress-clip（电量、下载、容量）
用 `clip-path` 从底部露出实心体，**别改几何**：
```css
.fill { clip-path: inset(calc((1 - var(--p)) * 100%) 0 0 0); transition: clip-path var(--t-med) var(--ez); }
```

### F. 色阶迁移（默认态 → 激活态）
`--ink-3` → `--accent`，`--t-fast` + `--ease-hover`。**颜色不许单独承担状态**（设计系统 §1）——必须叠第二通道：填充变化、形状变化（空心心 → 实心心）、或位置变化。

## 3. 时长与降级

- 按压 `--t-press` · 状态切换 `--t-fast` · 画出/进度 `--t-med` · 空态入场 ≤500ms（错峰 `--stagger`，封顶 0.3s）。
- **出场 ≈ 入场 ×0.7**，同路径反向。
- **只有加载环循环**，其余一次性；不 hover 触发、不滚动重放。
- `prefers-reduced-motion`：状态切换退成**瞬切或纯淡化**（去掉缩放与位移，Token 已把 `--pop/--shift` 归零）；draw-on 退成淡入；加载环保留旋转（它在传达「进行中」）但去掉脉冲与弹跳。

## 4. 交付：动效住在唯一的 Icon 入口

和 §8「一个 registry + 一个渲染入口」同构——**动效也只写一处**：

- **registry 只放静态图形**（`icons.ts`）；带 `--p` 的路径在 registry 里写默认值 `--p: 1`（静态渲染时就是完成态）。
- **`Icon` 组件承担动效**：接一个 `state` / `on` / `progress`，映射成 `data-*` 属性与 `--p`，CSS 在一处定义所有过渡。调用方只写 `<Icon name="check" on={done}/>`，**永远不在业务组件里手写 transition**。
- 新增一个会动的图标 = 在 Icon 里加一条 `data-state` 分支，不是复制一段动画到调用点。

## 5. 自检（在 §6 / §7 的流程里加这两步）

- **逐帧看中间帧**：把 `--p` 手动设成 `0 / .25 / .5 / .75 / 1`（浏览器里改变量即可，不用改工具），每一帧都要满足静态自检：**档位仍成立**（实心档不空心、线性档描边宽不变）、质心没漂、没有断层或穿模、暗色下没糊。中间帧崩了就是动效方案错了，不是时长问题。
- **一排一起看**：在 live card（`build-gallery.mjs serve`，浏览器）里同时触发同类图标——它们必须同速、同曲线、同幅度。contact sheet 只能看静帧，动效必须在 card 里复核。
