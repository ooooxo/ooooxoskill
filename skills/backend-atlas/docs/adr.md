# ADR 层：代码注释里的引用就是锚点

backend-atlas 怎么把 `docs/adr` 挂到图上、agent 怎么查和维护。改代码前想知道「这块为什么这样」、写完一个决策要落到代码上、体检报 ADR 问题时读。

## 原理

ADR 里的「为什么、放弃了什么」是叙述，图存不下，也不该从代码里猜。图要做的是让它和代码一直连着。
项目里本来就在注释里写 `（ADR 0036）`，这就是锚点，不另设格式；老 ADR 不用改一个字就全挂上图。build 每次（`viewer/adr.ts`，零 LLM）：

1. **扫引用**：两端源码（.cs .ts .tsx .vue .js .jsx .rs；跳过 node_modules / bin / obj / dist / target / build / wwwroot / docs / 点目录）里**注释中**的 `ADR NNNN`。字符串字面量里的不算。
   列表和区间也认：`ADR 0109/0147`、`ADR 0001、0002、0006`、`ADR 0018 / 0019`、`ADR 0020 §2 与 0023`、`ADR 0144–0161`。
2. **找编号**：从引用所在文件往上找，先找最近的 `docs/adr`（含 `archive/`），没有这个号就再往上一层，最远到仓库根。各端各用自己的一套编号。
3. **跨端**：引用前紧挨着写 `client` / `客户端（仓）` / `前端`，就去客户端那一端找；写 `server` / `服务端` / `后端`，就去服务端找；也可以直接写仓名（`MoriiServer ADR 0166`，仓名取根目录名和 git 仓库名，两端同名的不算）。图里没有那一端的，只计数（「指向本图外」）。
4. **落到哪张卡**：
   - 在方法里，落到那个方法的卡（端点、服务文件、前端文件）。
   - 在方法头上的注释里（下面 4 行内就是方法开头），落到那个方法。
   - 其余在方法外的，落到文件卡；没有文件卡，就落到这个文件所在的域。
   - 都没有就不上图（实体、迁移、测试），但仍会进 `by-file.md`。
5. **跟着卡挂上去**：ADR 跟着卡挂到域和业务循环。抽屉里有「为什么」一节，点一行就在编辑器里打开那份 ADR。

## 状态：照各项目实测的写法读

| 写法 | 算 |
|---|---|
| `status: accepted` · `- Status: Accepted` · `> Status: accepted（日期）` · `- 状态: 已定` | 有效（accepted · 已定 · 已接受 · 接受 · implemented · 已实施 · 进行中） |
| proposed · 提议 | 待确认 |
| superseded… · deprecated · 已作废 / 废弃，或者文件在 `archive/` 里 | 作废 |
| 没写状态 | 有效（domain-modeling 的格式里状态是可选的） |
| 其他词 | 状态读不出（列在 adr.md 里，补成上面的词） |

标题取第一行 `# `，去掉开头的 `ADR NNNN —`。

## 在图上看

- **浮岛「决策 N」**：有效的 ADR 按域分组列出，可以搜索。点一条，画布只亮它管着的卡，和看体检项一样；头部会显示「正在看：ADR …」，Esc 退出。
- **卡片角标**：卡右上角的「📄 N」表示有几条有效 ADR 管着这张卡（域卡算上框里的子卡）。
- **抽屉「为什么」**：点卡后列出管着它的 ADR，点一行在编辑器里打开原文。循环抽屉里也有这一节。

## 体检里的两项（只列出，不挡出图）

| 项 | 怎么处理 |
|---|---|
| 引用了作废的 ADR | 决策换了、代码没跟上：要么改代码，要么把注释改成指向接替它的那条。决策其实还有效的话，写新 ADR 把它立回来 |
| 引用的 ADR 不存在 | 编号写错了，或者指的是另一端却没写限定词：改成 `client ADR 0018` / `server ADR 0161` |

## agent 怎么用

- **读（改代码前）**：`grep <文件名> .atlas/by-file.md` 看列出了哪些 ADR，只读这几条。被问「为什么这么设计」时，用关键词 grep `.atlas/adr.md`（一条一行，别整个读进来）。
- **写（做了一个不显然的决定之后）**：
  1. ADR 正文按 domain-modeling（ADR-FORMAT）或 backend-discipline（ADR-TEMPLATE）写进 `docs/adr`，这里不重复规定格式。
  2. **agent 起草、用户还没拍板的，状态写 proposed**。「为什么、放弃了什么」只能来自用户说过的话、已有的 ADR、提交说明，不编。
  3. 在代码真正起作用的地方加注释引用：行尾 `// …（ADR 0042）`、方法体内，或者方法头上的注释里都行。
  4. 重跑 `run.sh`，在 adr.md 里确认它挂到了预期的域。
- **推翻旧决策**：写新 ADR（supersedes 旧号）；旧的改状态或挪进 `archive/`；代码里的引用改指新号。重跑后，「引用了作废的 ADR」里就不再有它。
- 不落在代码上的决策（部署、流程、取舍）可以没有引用，会列在 adr.md 的「没有代码引用的有效 ADR」里，不算问题。

## 清理：长期维护，删掉没用的

ADR 会越积越多（实测一个项目作废的就有一百多条），全留着只会让 agent 检索时多读噪音。整理图的同时顺手清理：

1. **能删的**：看 adr.md 的「可以删」。build 确定性地算出来，三条同时满足：
   - 已作废（superseded / deprecated / 在 `archive/` 里）。
   - **仓库里没有任何被 git 跟踪的文件再指着它**：代码注释、字符串、`CLAUDE.md` 的不变量、`CONTEXT.md`、docs、css、csproj、html 都查。这里按偏保守的规则：「ADR」后面直到这一句结束出现的四位数都算，`archive/0199` 这种链接也算。`docs/adr/` 自己、`.atlas/`、没进 git 的文件不算。另一个仓里写明本端的（「服务端 ADR 0040」）也算。
   - 没有任何有效 ADR 的正文提到它，文件链接 `[0254](archive/0254-…)` 也算提到。只有作废 ADR 之间互相提到的，不拦。
2. **列给用户确认**：编号 + 标题列成一张清单，用户点头后再 `git rm`，并在提交说明里列出删掉的编号。git 里留着历史，要找回就 `git log -- docs/adr/<文件>`。
3. **编号不复用**：删掉的号不再用。最大号的那份别删，因为新 ADR 是按「最大号 + 1」取号的。
4. **把要删的变成能删的**：
   - 作废了但代码还在引用：把注释改成指向接替它的那条。
   - 作废了但还被有效 ADR 提到：确认那条有效 ADR 的正文已经写清楚当初为什么推翻它，再把提到它的那句删掉或改成指向新号。
   - 有效但已经不成立：把状态改成 superseded、写清楚被谁取代，下一轮重跑它就进「可以删」。
   - **合并长链**：同一件事被一串 ADR 反复修订时（A 被 B 修订，B 又被 C 修订），写一条新的 ADR，把现行的决定和关键的取舍收在一起，状态写 proposed，supersedes 整条链。用户确认后，旧的就进「可以删」。
5. 删完重跑 `run.sh` 复核：「引用的 ADR 不存在」不能变多（变多就说明删了还有人指着的，用 git 恢复）；「可以删」清零。项目有自己的 ADR 索引脚本的（比如 `scripts/adr-index.mjs`），删完重新生成。

adr.md 里同时还有两类整理活，需要改正文、要判断，不会自动删：「文档还指着作废的 ADR」（CLAUDE.md / CONTEXT.md 里过时的引用）和「编号重复」（正文和 archive/ 同号）。

agent 不自己决定删哪条：「可以删」只说明没人再指着它，删不删由用户拍板。
